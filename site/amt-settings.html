AMT settings explained

This page explains the Intel AMT settings OpenLAMT shows, the way an administrator needs them: what each one does, when to change it, and what can go wrong.

Before you change anythingMost settings on this page decide whether you can still reach the device over the network. A wrong value often needs a visit to the device: its BIOS extension (Intel MEBx) is then the only way back. OpenLAMT asks first and names the device, but it cannot undo a change for you.

How Intel AMT works

Intel AMT is part of the Intel management engine (ME), a small computer inside the chipset. It has its own firmware, its own clock and its own network stack. It shares the network card of the device but answers on its own ports. That is why AMT works while the operating system is off, hangs or is not installed yet.

AMT must be activated (provisioned) before anyone can use it over the network. Activation sets the admin password, the control mode and usually TLS. You do it in the BIOS extension Intel MEBx (often Ctrl+P at boot) or with Intel's provisioning tools. OpenLAMT works with devices that are already activated.

Control mode: ACM and CCM

The control mode is fixed at activation. OpenLAMT shows it in the status bar of the device window and on the Hardware page.

Admin Control Mode (ACM)Client Control Mode (CCM)
How it is activatedIn MEBx at the device, or remotely with a provisioning certificateFrom the operating system of the device, without proof of ownership
User consentOptional: None, KVM only or AllAlways required for remote screen, media, console and boot changes
Typical useServers, lab machines, devices without a person in frontDesktops where a user should see and allow every remote session

Some functions need more rights than CCM grants. If a device refuses a change, check its control mode first.

Host name, domain and ping

Host name and Domain
The name AMT uses for itself, for example labserver in example.com. With Dynamic DNS, AMT registers this name in DNS. Change it when you rename the device. Risk: favorites that use the old name stop working until you edit them. Asks orange.
Respond to ping
Lets AMT answer an ICMP ping. Turn it on to check reachability with ping or a monitoring tool. It changes nothing else.
Dynamic DNS
AMT registers its own host name in DNS. Use it when the device gets its address by DHCP and your DNS server accepts dynamic updates. Risk: the device may then be reachable under a different name than in your favorites, and favorites that use the name stop working until you edit them. Asks orange.

Environment detection

Intranet domains tell AMT which networks are “inside”. AMT compares the DNS suffix it gets from DHCP with these domains. If none matches, AMT assumes it is outside your network and closes its network access there.

When you need it: only with remote access from outside through a management server (CIRA). OpenLAMT does not use CIRA. On a home or lab network, leave the list as it is.

What can go wrong: a wrong or missing entry can make AMT stop answering on your local network. Only the BIOS (MEBx) at the device can then fix the list. Asks red.

Network address and IP sync

On the wired port, AMT and the operating system share the network card. AMT still needs an IPv4 address of its own configuration.

DHCP
AMT asks the DHCP server for its address, like the operating system. Usually both get the same address. This is the simplest choice.
Static
AMT uses the address, subnet mask, gateway and DNS servers you enter. Use it in networks without DHCP. OpenLAMT turns IP sync off when it sets a static address.
IP sync
With a static address in the operating system, AMT can take over that address through the Intel management service (LMS) of the device. AMT then follows the operating system. OpenLAMT shows the address it reads, and choosing Static replaces IP sync with a fixed address.

What can go wrong: a wrong address, mask or gateway makes the device unreachable. Only the BIOS (MEBx) at the device can fix it. Asks red. OpenLAMT changes only the wired port. IPv6 is not supported.

Remote features (redirection)

AMT “redirects” the screen, a drive and a serial port of the device to your computer. Each feature can be switched on its own.

KVM
Keyboard, video and mouse: the remote screen.
Media redirection (IDE-R)
A virtual CD drive for ISO images and folders.
Serial over LAN (SOL)
A virtual serial port for the text console.

Turning a feature on asks nothing. Turning it off asks orange, because open sessions of that kind end at once. You can turn it on again from OpenLAMT. When you open Media or Console on a device where IDE-R or SOL is off, OpenLAMT offers to turn it on.

Turn off what you do not use. Each feature is another way into the device for anyone with a valid AMT account.

One Click Recovery and remote erase

Newer devices (Intel AMT 16 and later) have a boot service that can do more than pick a boot device. Each of its two features has a switch under Remote features and must also be on in the BIOS. Switching them on or off asks nothing. If the BIOS has a feature off, AMT refuses the switch: “Turn it on in the BIOS first.”

One Click Recovery (HTTPS boot)
Lets AMT start the device once from an image over HTTPS: from a file on your computer or from a URL. You start it in Boot Options. The device checks the HTTPS server against its trusted roots.
Remote Platform Erase
Lets AMT have the BIOS erase the drives at the next start, and optionally clear the TPM, reset the BIOS settings and unconfigure AMT. You start it with Erase drives. Older devices instead offer Remote Secure Erase of the boot drive, without a switch.

What can go wrong: while One Click Recovery is on, anyone with a power control account can start the device from an image of their choice. While Remote Platform Erase is on, anyone with an account that may set boot options can erase the device. Turn them on when you need them and off again afterwards.

User consent

User consent makes AMT ask a person at the device before a remote session. AMT shows a six-digit code on the screen of the device, on top of whatever runs there. The remote user must enter that code. This proves that someone at the device agrees.

None
No consent. Remote sessions start at once.
KVM only
Consent for the remote screen. Media and console start without it.
All
Consent for every redirection session and for boot changes: Reboot to BIOS, Boot Options, One Click Recovery and Erase drives ask for the code too.

When you need it: on desktops where a person works and should see every remote session. On a server room machine, nobody can read the code, so None fits there.

In Client Control Mode the device always requires consent, and the setting cannot be lowered. Some devices do not allow remote changes of this setting at all; the choice is then disabled. Plain power actions such as Power On or Reset never need consent.

AMT clock

AMT has its own clock. It uses it for log entries, wake alarms and the validity of certificates. A clock that is far off makes log times misleading and can break TLS. The Settings page shows how far the AMT clock is ahead of or behind your computer. Sync Now sets it to the time of your computer. It asks nothing.

TLS

With TLS, AMT encrypts management and redirection traffic (ports 16993 and 16995). Without TLS, a digest of the password and every keystroke travel in clear on the network. Use TLS everywhere you can.

TLS is set up at activation. The Settings page shows the SHA-256 fingerprint of the certificate AMT presents. Change… lists the certificates stored on the device with their expiry dates and lets you pick another one. AMT then restarts TLS with it, and OpenLAMT updates the fingerprint it trusts for this device. Asks orange, because a wrong certificate can break the connection for other tools.

OpenLAMT pins the certificate on the first connection. See TLS and certificate pinning.

Certificates and trusted roots

Intel AMT keeps its own certificate store. It holds the TLS certificate with its private key, other certificates, and trusted roots: certificate authorities whose servers the device trusts, for example for HTTPS boot. The Certificates page lists them, imports new ones and deletes old ones.

  • Your own TLS certificate: import it with its private key as a .p12 or .pfx file, then choose it under TLS certificate on the Settings page. AMT accepts only RSA keys.
  • HTTPS boot from your own server: import the root of your server’s certificate as trusted root.
  • Expired certificates are marked red. The device refuses to delete the certificate it uses for TLS; choose another one first.
  • The store has limited space. A full store says “… has no space for more certificates.” Delete what you no longer need.

Accounts and realms

AMT controls access with realms: groups of functions an account may use. OpenLAMT bundles them into six permissions. A permission counts as given when the account has all its realms. Realms outside these groups stay as they are when you edit an account.

Power controlRemote ControlPower actions and boot options
KVM, media, consoleRedirectionRemote screen, IDE-R and SOL sessions
HardwareHardware AssetThe Hardware page
Event logEvent Log ReaderReading the event log
Audit logSecurity Audit LogReading the audit log and changing its settings
SettingsPT Administration, General Info, Network TimeThe Settings page

Access decides where an account may sign in from: Network, Local (software on the device) or Both.

Give each person or tool its own account with only the permissions it needs. A helpdesk account with Power control and KVM, media, console can help users without changing AMT. OpenLAMT works with such accounts and shows what they may not read; see Limited accounts.

Audit policy

The audit log answers “who did what, from where and when” for AMT itself. The audit policy decides which events AMT records and what happens when the log is full. OpenLAMT groups the events in twelve groups in plain words; set them in the audit log settings.

  • Leave recording on. While it is off, changes to the device leave no trace.
  • When the log is full: overwriting the oldest entries keeps recording. A minimum age keeps entries for a number of days first. Stop recording keeps every entry, but while the log is full, Intel AMT blocks critical actions until someone clears the log.
  • Clearing the log cannot be undone. The log then holds one entry that says it was cleared, so the clearing itself stays visible.

Event forwarding

Besides its own event log, Intel AMT can send events as they happen to a listener on the network, for example a SIEM collector. It uses WS-Management events (WS-Eventing): AMT sends an HTTP request per event, with or without an acknowledgement from the listener, optionally signed in with Digest. AMT does not send syslog.

You need a listener that accepts WS-Management events. OpenLAMT only sets up the target on the device; it does not receive or show forwarded events. Set targets with Forwarding… on the event log. AMT cannot change a target: delete it and add a new one.

Power policies

The power package decides in which power states of the device AMT stays on. The states have short names:

StateMeaning
S0The device runs.
S3Sleep (suspend to RAM).
S4Hibernate (suspend to disk).
S5Soft off: switched off, but on power.

A package named, for example, “Desktop: on in S0, ME wake in S3, S4-5” keeps AMT reachable while the device sleeps or is off. Only then can you power the device on remotely. A package “on in S0” saves a little power but turns AMT off with the device. Then nobody can power it on over the network until someone switches it on at the device. OpenLAMT therefore asks orange before such a change.

The names and the list of packages come from the device. Some devices refuse frequent changes of the package to protect their flash memory: “its flash write limit is reached. Try again later.”

The Idle timeout sets after how many minutes without requests the management engine goes to power saving. It wakes again on the next request. Raise it if AMT turns off before you finish working.

Turn off AMT

Turn Off… in the Danger zone switches AMT off on the network. The device then stops answering at once: no power control, KVM or media, not from OpenLAMT and not from any other tool. This cannot be undone remotely. Only the BIOS (MEBx) at the device can turn it back on. Asks red.

Use it when you retire a device, hand it to someone else, or want to be sure nobody manages it over the network.
