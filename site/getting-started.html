Getting started

Install OpenLAMT, connect to your first device and learn how OpenLAMT keeps the connection safe.

What you need

  • A device with Intel AMT that is activated and reachable over the network. OpenLAMT uses the ports 16992 to 16995.
  • The user name and password of an AMT account on that device. The built-in account is usually admin.
  • macOS on Apple Silicon, Windows on x64, or Linux on x64.
  • On Linux: a Secret Service provider such as GNOME Keyring or KeePassXC, so OpenLAMT can save passwords.

Intel AMT must be set up on the device before OpenLAMT can use it. You do this once in the BIOS of the device (Intel MEBx) or with Intel's provisioning tools. OpenLAMT does not activate AMT for you.

Install

Download the file for your system from the Releases page:

SystemFile
macOS (Apple Silicon)OpenLAMT-<version>-macos-arm64.dmg
Windows (x64)OpenLAMT-<version>-windows-x64.zip
Linux (x64), any distributionOpenLAMT-<version>-linux-x64.AppImage
Linux (x64), Debian, Ubuntu and derivativesOpenLAMT-<version>-linux-x64.deb

The builds are not code-signed. macOS and Windows therefore warn on the first launch. The steps below show how to start the app anyway.

macOS

  1. Open the disk image (.dmg).
  2. Drag OpenLAMT.app onto the Applications shortcut next to it.
  3. Start OpenLAMT once. Gatekeeper blocks it, because the app has only an ad-hoc signature.
  4. Open System Settings > Privacy & Security and click Open Anyway next to OpenLAMT. On macOS 15 Sequoia and later, right click > Open no longer works for this.

Instead of step 4 you can remove the quarantine attribute in a terminal:

xattr -dr com.apple.quarantine /Applications/OpenLAMT.app

On the first connection, macOS asks whether OpenLAMT may find devices on the local network. Allow it. If you said no, see Troubleshooting.

Windows

  1. Unzip the file.
  2. Start OpenLAMT.exe. No installer is needed.
  3. SmartScreen shows “Windows protected your PC”. Click More info, then Run anyway.

Linux: AppImage

The AppImage runs on any distribution with glibc 2.35 or newer (for example Ubuntu 22.04 and later). Make it executable and start it:

chmod +x OpenLAMT-<version>-linux-x64.AppImage
./OpenLAMT-<version>-linux-x64.AppImage

If your system lacks FUSE 2, start it with --appimage-extract-and-run. The AppImage uses the OpenGL and X11 or Wayland libraries of your desktop.

Linux: .deb

sudo apt install ./OpenLAMT-<version>-linux-x64.deb

apt installs the libraries the app needs. Start OpenLAMT from the application menu or with openlamt. The package recommends gnome-keyring. Without a running Secret Service provider, OpenLAMT cannot save passwords.

Connect to your first device

  1. Click Quick Connect at the bottom of the sidebar.
  2. Enter the Host/IP of the device, for example 192.0.2.10 or lab.example.com. Do not add a port.
  3. Enter the Username and the Password of the AMT account.
  4. Leave Use TLS on if the device has TLS set up. Most activated devices do.
  5. Click Connect. The device window opens.

Click Save as favorite instead to keep the device in the sidebar. The password then goes into the keychain of your system.

Password prompt

If no password is saved, OpenLAMT asks for it when you connect: Password for admin@192.0.2.10. Tick Save password to keep it in the keychain. OpenLAMT saves a password only after the device accepted it.

User consent code

Some devices ask a person at the device to agree before a remote session starts. The device then shows a six-digit code on its own screen. OpenLAMT asks for it in the dialog User consent. Ask the person at the device for the code and enter it. Without the code, the session does not start.

When AMT asks for consent depends on the control mode and the user consent setting of the device. Besides remote sessions, the same dialog appears before Reboot to BIOS, Boot Options and Erase drives on devices that require consent for boot changes. A cancelled dialog changes nothing.

TLS and certificate pinning

With TLS, OpenLAMT encrypts the connection to the device. It uses port 16993 for management and 16995 for the remote screen, console and media. Without TLS it uses 16992 and 16994. Then passwords and data travel unencrypted, and OpenLAMT shows “Without TLS” next to the device.

Most AMT devices use a self-signed certificate. No public authority can confirm it. OpenLAMT therefore uses trust on first use:

  1. On the first TLS connection, OpenLAMT shows the SHA-256 fingerprint of the device certificate and asks Trust this device?
  2. Compare the fingerprint with the one the device shows, for example in the BIOS (MEBx) or in your provisioning records. Click Trust device if it matches.
  3. For a favorite, OpenLAMT saves the fingerprint in the keychain. Later connections check it silently. A Quick Connect to a device that is no favorite accepts the certificate for this connection only and asks again next time.
  4. If the certificate ever changes, OpenLAMT stops the connection and shows Certificate changed.

When the certificate changes on purpose

A device gets a new certificate after a new provisioning, a firmware reset or when an administrator replaces it. If you know why it changed:

  1. Select the favorite and click the edit symbol .
  2. Turn on Reset fingerprint under Advanced and click Save.
  3. Connect again and check the new fingerprint before you trust it.

If you change the TLS certificate of a device in OpenLAMT itself (Settings page), OpenLAMT updates the saved fingerprint on its own.

If you do not know why it changed, do not reset the fingerprint.Someone may be between your computer and the device. Check the network first.

Where OpenLAMT keeps your data

WhatWhere
Favoritesopenlamt/favorites.json in your configuration folder: ~/Library/Application Support (macOS), %AppData% (Windows), ~/.config (Linux)
Passwords and certificate fingerprintsThe system keychain, services openlamt and openlamt-fingerprint. Never in a file.
Temporary ISOs of mounted foldersOpenLAMT/ider in your cache folder, deleted on unmount
Screenshots and recordingsThe folder you choose in Settings, or where the save dialog puts them
Downloaded updates~/Downloads, only when you click Update
MCP server settings and action logopenlamt/openlamt-mcp.json and openlamt/openlamt-mcp-actions.log in the configuration folder, only if you use openlamt-mcp

OpenLAMT changes nothing on a device that you did not start. On the network it talks only to your AMT devices and, once per start, to api.github.com for the update check. You can turn the update check off. Only during One Click Recovery from a file does OpenLAMT accept connections: it serves the image on the port you choose, for at most 10 minutes.

Remove OpenLAMT

  1. Delete the app: OpenLAMT.app, the folder with OpenLAMT.exe, the AppImage file, or run sudo apt remove openlamt.
  2. Delete the openlamt folder in your configuration folder and, if present, the OpenLAMT folder in your cache folder.
  3. Optionally delete the keychain entries of the services openlamt and openlamt-fingerprint.
