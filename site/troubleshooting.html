Troubleshooting

OpenLAMT says in plain words what went wrong. This page lists the common messages, what they mean and what to do.

The app does not start

macOS: “OpenLAMT cannot be opened” or “Apple could not verify”
The app is not notarized. Open System Settings > Privacy & Security and click Open Anyway, or remove the quarantine attribute. See Install on macOS.
Windows: “Windows protected your PC”
SmartScreen does not know the unsigned file. Click More info, then Run anyway.
Linux: the AppImage does not start
Without FUSE 2, start it with --appimage-extract-and-run. It needs glibc 2.35 or newer. On older systems, use the .deb or build from source.

Cannot connect

“192.0.2.10 cannot be reached from this computer.”
Check the address and the network. The device must be on, connected by cable (or Wi-Fi with AMT Wi-Fi set up), and in a network your computer can reach.
On macOS, every device is unreachable
macOS blocks apps from the local network until you allow it. Open System Settings > Privacy & Security > Local Network and turn OpenLAMT on.
“192.0.2.10 did not answer in time.”
The device is off the network, or a firewall drops the packets. AMT uses the ports 16992 to 16995.
“192.0.2.10 refused the connection on port 16993.”
Something answers at this address, but not AMT. Check that the address belongs to the AMT interface, and that AMT is activated. A network scan shows which addresses run AMT.
“… does not accept TLS connections on port 16993.”
TLS is not set up on the device. Turn off Use TLS for this favorite and connect again.
“… does not accept connections without TLS on port 16992.”
Many devices allow only TLS. Turn on Use TLS and connect again.
“The TLS handshake with the device failed.”
The device uses TLS settings OpenLAMT does not support, for example a very old protocol version. A firmware update of the device often helps.
“The name lab.example.com could not be found.”
DNS does not know the name. Check it, or use the IP address of the device.
“Authentication failed: wrong username or password.”
The device rejected the login. AMT user names and passwords are case-sensitive. The admin password is the one set at activation, for example in MEBx.
“Certificate changed”
The certificate of the device no longer matches the trusted one. Read When the certificate changes on purpose before you do anything.
“IPv6 addresses are not supported.”
Use the IPv4 address or a host name.

Permission messages

“This account is not allowed to do this on the device.”
The account lacks the permission for this action. Sign in with an account that has it, or ask an administrator to add it on the Users page.
“Not allowed for this account”, “Power: not allowed”, “N/A”
The account may not read this part. Everything else works. See Limited accounts.
“The device does not allow changing this setting.”
The device itself locks the setting, for example the consent policy in Client Control Mode.

User consent

OpenLAMT asks for a consent code
The device shows a six-digit code on its screen. Ask the person at the device for it. See User consent.
“The device did not accept the consent code.”
Check the six digits on the device screen and try again. The code is valid for a limited time; a new attempt shows a new one. Nothing was changed on the device.
Nobody is at the device
On a device in Admin Control Mode, an administrator can set User consent to None on the Settings page. In Client Control Mode, consent is always required.

Remote screen (KVM)

“The device refused the KVM session (status …). Another KVM session to this device may still be open.”
AMT allows one KVM session per device. Close the other one: a second OpenLAMT window, another tool such as MeshCommander, or an AI agent through openlamt-mcp.
“The device refused to enable KVM … KVM may be disabled in the AMT settings of the device.”
Turn on KVM on the Settings page. Some devices also need KVM enabled in MEBx.
The screen stays black
AMT shows only the output of the Intel graphics in the processor. With a separate graphics card in use, KVM stays black. Otherwise the screen may just be asleep: move the mouse or press a key. A device that is off shows nothing until you power it on.
“KVM disconnected after 30 minutes without input.”
OpenLAMT closed an idle session. Change the time in Settings.
Key combinations do not reach the device
Your computer keeps some combinations for itself. Use the Ctrl+Alt+Del button. See Keyboard.
Type Clipboard types wrong characters
The layout does not match the device. Choose the right one under Keyboard.
The picture is slow
Switch Quality to Low quality (256 colors).

Serial console

“The device did not start the serial console.”
Serial over LAN may be off. Turn it on on the Settings page and try again.
The console stays empty
The console only shows what the device sends to its AMT serial port. The BIOS or the operating system must use that port as console. On Linux, add a kernel option such as console=ttyS1,115200 for the right port; the port number differs between devices.

Media

“This device does not support media redirection (IDE-R).”
The device does not offer media redirection, so OpenLAMT cannot mount images on it.
The device does not boot from the ISO
Use Restart from ISO… or Boot from ISO on next start. Check that the image suits the boot mode of the device: a mounted folder boots only over UEFI and needs EFI/BOOT/BOOTX64.EFI. With Secure Boot, the boot loader on the image must be signed.
Folder errors such as “A file in the folder is 4 GiB or larger”
A folder becomes an ISO image first, which has limits: each file under 4 GiB, names up to 103 characters, names that differ in more than upper and lower case. The message names the limit.
“The device closed the media session.”
AMT ended the session. Mount the image again.

Boot options and erase

“The device is asleep. Waking it does not restart it, so the boot options would not apply.”
Boot Options, One Click Recovery and Erase drives refuse a sleeping device. Wake it with Power On, wait until it runs, then try again. Nothing was changed.
“… the next restart of the device may still use them.”
A step failed after the boot options were written, and OpenLAMT could not clear them again. Connect again and start Boot Options with Hard disk (default order).
“… the next restart of the device may still erase the drives.”
The same for an erase. Do not restart the device if you do not want the erase. Connect again and start Boot Options with Hard disk (default order): it clears the erase before the restart.
“Port 8443 is in use. Choose another port.”
Another program uses the port for One Click Recovery from a file. Enter another port in the dialog.
“Lab-Server did not download the image. Check the firewall on this computer.”
The device did not fetch the image within 10 minutes. Allow incoming connections on the port, check that the chosen address is reachable from the device, and that HTTPS boot is on in its BIOS.
“OpenLAMT could not remove the temporary root certificate …”
Delete “OpenLAMT recovery (temporary)” on the Certificates page.
“Turn it on in the BIOS first.”
One Click Recovery or Remote Platform Erase is off in the BIOS of the device. Only the BIOS at the device can turn it on.
“Remote Platform Erase needs a TLS connection.”
Turn on Use TLS for the favorite, connect again and try again.
“Remote Platform Erase is off”
Turn on Remote Platform Erase under Remote features on the Settings page.

Certificates and forwarding

“The file is not a certificate.”
Choose a .pem, .cer or .crt file for a trusted root, or a .p12 or .pfx file for a certificate with key. The switch at the top of the import dialog decides which.
“Wrong password for the .p12 file.”
Enter the password the file was exported with. The dialog stays open.
“No certificate in the file matches its private key.” or “The key in the file is not an RSA key.”
Export the file again with the certificate that belongs to the key. Intel AMT accepts only RSA keys.
“Lab-Server has no space for more certificates.”
Delete certificates or keys the device no longer needs, then import again.
“Certificate in use”
The device uses this certificate for TLS. Choose another TLS certificate on the Settings page first.
“Lab-Server refused the target: …”
The device did not accept the forwarding target. The reason comes from the device; check the address and the sign-in.
“No permission for audit settings”
Sign in with an account that has the Audit log permission.

Passwords and keychain

“The keychain could not be used: …”
On Linux, start a Secret Service provider such as GNOME Keyring or KeePassXC and unlock it. On macOS, unlock the login keychain.
“The trusted certificate could not be read from the keychain, so OpenLAMT did not connect.”
The keychain is locked or unavailable. OpenLAMT refuses to connect without the trusted fingerprint. Unlock the keychain and try again.
“New password not saved”
The device took a new password, but the keychain did not. Copy the password from the dialog now. It is shown only once.

Updates

“Could not check for updates: GitHub's rate limit is reached.”
GitHub limits requests per address. Try again later.
The update did not install
The package stays in ~/Downloads, and the window says how to install it. See The update window.

Report a problem

Open an issue on GitHub. Name your system, the OpenLAMT version, the AMT version of the device and the exact message. Leave out host names, addresses, serial numbers and passwords: issues are public.
