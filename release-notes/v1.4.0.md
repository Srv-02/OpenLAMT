- AI agents can now use OpenLAMT on Linux servers and VMs without a system keychain: trusted certificates can be kept in a private file instead
- If you rename your own login on a device, the saved device follows, even when the system keychain cannot be read
- After you change a device login through your AI agent, OpenLAMT tells you exactly where the new password still has to go
- The app itself only changes in one rare case: a renamed login now also reaches the saved device when the keychain is locked

## Notes
- To keep trusted certificates in a file, set "certificates": {"pin_file": true} in the openlamt-mcp config and run "openlamt-mcp trust" once for each device. The app keeps its trusted certificates in the system keychain.
- The builds are not code-signed. macOS and Windows warn on the first launch; the README explains how to open the app anyway.
