MCP server (openlamt-mcp)

openlamt-mcp lets an AI agent use your OpenLAMT favorites: find devices in the network and manage favorites, read status, hardware, logs, settings and accounts, control power, boot from an ISO, look at the screen, type, use the serial console, and change AMT settings and accounts. It runs on your computer and opens no network port. It also works without the app, for example on a Linux server without a desktop.

What it is

MCP (Model Context Protocol) is a standard way for AI apps to call tools. Claude Desktop, Claude Code and other MCP clients start openlamt-mcp and talk to it over standard input and output. The agent then sees tools such as list_devices or power_action.

Install

openlamt-mcp is a separate program next to the app. Download the archive for your system from the Releases page (opens in a new tab) and unpack it anywhere. It holds a single program without dependencies, with its license files.

SystemArchive
macOS (Apple Silicon)openlamt-mcp-<version>-macos-arm64.tar.gz
Windows (x64)openlamt-mcp-<version>-windows-x64.zip
Linux (x64)openlamt-mcp-<version>-linux-x64.tar.gz

The program is not code-signed. On macOS, remove the quarantine attribute once:

xattr -d com.apple.quarantine openlamt-mcp

On Windows, SmartScreen may warn on the first start. To build it yourself instead: go build -o openlamt-mcp ./cmd/openlamt-mcp (no C compiler needed). openlamt-mcp --version prints the version.

Then add it to your MCP client:

{"mcpServers": {"openlamt": {"command": "/path/to/openlamt-mcp"}}}

The app’s update check never offers these archives. Update openlamt-mcp by downloading the new archive.

Devices, passwords and TLS

  • The agent sees your OpenLAMT favorites by their names. With the group favorites it can also scan the network and add, change and delete favorites (see Scan and favorites). It never sees or sets a device password. The app and openlamt-mcp can run at the same time and share the favorites safely.
  • openlamt-mcp finds device passwords itself: in the system keychain (where the app saves them), else through your password command. Passwords never pass through the MCP connection and never appear in answers, questions or logs.
  • A TLS device works only after a person trusted its certificate: in the app, with openlamt-mcp trust in a terminal, or in the question of add_favorite. The MCP server never trusts a certificate by itself.
  • list_devices shows for each favorite whether a password is found (password_found, password_source) and whether its certificate is trusted (certificate_pinned), so the agent can tell you what is missing. It contacts no device.
  • Devices without TLS work, with a warning in each answer.
  • If a device asks for user consent, the agent has to ask a person at the device for the six-digit code on its screen and pass it as consent_code (boot_to_bios, kvm_connect, sol_connect, media_mount).

Tools

The tools come in groups. You switch groups on and off in the config file; a tool of a group that is off does not exist for the agent.

destructive also covers every power action except power on, boot_to_bios on a device that is not off, and boot_from_iso on a device that is not off. Without it these calls are refused. Boot options, One Click Recovery, erasing drives, certificates, Wi-Fi, System Defense, the power policy, wake alarms, event forwarding and the audit log settings are only in the app.

Scan and favorites

  • scan_network runs the scan of the app: a network such as 192.0.2.0/24, a range such as 192.0.2.10-192.0.2.80 or one address, up to 4,096 addresses. It sends no password and changes nothing. It returns address, DNS name, AMT version, whether TLS is offered and whether the device is a favorite already. It is not tied to a favorite, so allowed_devices does not limit it; switch the group favorites off if the agent must not scan.
  • add_favorite saves a favorite with name, host, user name and TLS, as the app does, never with a password. Names must be unique. It asks only with require_client_confirmation. With TLS and an MCP client that can ask, the question shows the certificate fingerprint (SHA-256) of the device, and the certificate is trusted only if you tick it. Otherwise the favorite stays untrusted until a person runs openlamt-mcp trust.
  • update_favorite changes name, host, user name or TLS, delete_favorite deletes a favorite with its password in the keychain and its certificate. Both are orange: they always ask you, and a client that cannot ask gets a refusal. A new host or user name deletes the saved password and the trusted certificate, as in the app; no password follows the favorite to the new host, a person provides it again.
  • With allowed_devices, the agent can add and rename favorites only to names in that list.

Power

power_action follows the rules of the Power menu: a running device refuses on, a device that is off takes only on, and shutdown needs the device to offer it (device_status says so). Power off, power cycle and shutdown close an open KVM session first, because AMT refuses them while KVM is open.

Remote screen

  • kvm_connect opens the KVM session of a device and keeps it for the following calls.
  • kvm_screenshot returns the screen as an image sized for AI models: by default at most 1280 pixels on the longest side, as JPEG.
  • kvm_send_keys presses keys and combinations such as Ctrl+Alt+Delete. kvm_mouse moves, clicks and scrolls at a point of the last screenshot. kvm_type_text types text in the keyboard layout of the favorite.
  • AMT allows one KVM session per device. While the agent holds it, the app cannot connect KVM to that device, and the other way round. The session closes with kvm_disconnect, after five minutes without a call, or when the MCP client stops the server.
  • If KVM is off on the device, kvm_connect turns it on. That is a settings change: it needs the group settings and, with require_client_confirmation, your answer to a question. Without settings, the call says what to turn on. The wake key that kvm_connect presses on a new session needs kvm_input.

Serial console

  • sol_connect opens the serial console (Serial over LAN) of a device. Its output goes into a buffer of 1 MiB per device.
  • sol_read returns the output as plain text and goes on where the last read ended.
  • sol_type_text writes printable ASCII text, with line breaks as Enter. sol_send_keys presses keys such as Ctrl+C, Up or F10 as xterm sequences. A BIOS setup over the serial console often expects other codes for function keys; KVM works there too.
  • One serial console session per device: while the agent holds it, the app’s Console view cannot connect, and the other way round. It closes with sol_disconnect, after five minutes without a call, or when the server stops.
  • If SOL is off, sol_connect turns it on under the same rules as kvm_connect.

Media

  • media_mount mounts an .iso file or a folder on a device as a read-only CD drive. The agent gives its absolute path on the computer that runs openlamt-mcp. A folder becomes a temporary ISO first, as in the app. A big folder takes a while, and the build runs within the tool call, so a client with a short tool timeout may abort it.
  • media_boot_next makes the device boot from the image at its next start. boot_from_iso restarts it from the image now; a device that is off is only powered on. media_status shows what is mounted and how fast the device reads it.
  • The image stays mounted until media_unmount, until the device ends the session, or until the client stops the server. The boot option set with media_boot_next is cleared then. If a boot from the image fails halfway, media_unmount clears the boot option as well.
  • One media session per device: while the agent holds it, the app’s Media menu cannot mount on that device, and the other way round.
  • If media redirection (IDE-R) is off, media_mount turns it on, and it stays on. That needs the group settings. With require_client_confirmation, the mount question says that IDE-R will be turned on.
A mounted folder can be read on the device.Whoever uses the device, or its remote screen, can read every file of a mounted folder. openlamt-mcp therefore refuses some folders, but the list cannot cover every place with secrets. Set media.allowed_paths to the folders with your images.

What media_mount does to protect your files:

  • It resolves links first and mounts only the resolved path. It checks right before it opens the file that it is still the one it checked, and builds a folder image so that nothing outside the folder can end up in it. Links inside the folder are left out.
  • It never mounts your home folder itself, a folder above it, or the folders that hold credentials and settings: ~/.ssh, ~/.gnupg, ~/.aws, ~/.azure, ~/.config, ~/.local/share, ~/.local/state, ~/.kube, ~/.docker, ~/.password-store, ~/.mozilla, ~/.thunderbird, ~/.pki, ~/.claude, ~/.cargo, ~/.m2, ~/.gradle, ~/.terraform.d, ~/.var/app, ~/snap, all of ~/Library on macOS, %APPDATA% and %LOCALAPPDATA% on Windows, and the OpenLAMT configuration folder with the favorites, openlamt-mcp.json and the action log.
  • It recognizes these folders by the file system, not by their spelling: a link, a bind mount, a macOS firmlink or a Windows junction to one of them is refused too, and a folder image stops when one of them turns up inside.
  • On Windows, \\?\ and \\.\ paths and administrative shares such as \\host\C$ are refused.

AMT settings and accounts

get_settings and list_users show what the app’s Settings and Users pages show. A section the account may not read is listed in not_permitted, one the firmware lacks in not_available. The other tools change what those pages change, with the same confirmation levels:

Level in the appChangesWhat openlamt-mcp does
nonePing, switching a feature on (also by kvm_connect, sol_connect or media_mount), raising user consent, the clock, adding, editing or disabling another accountAsks you in the MCP client only with require_client_confirmation.
orangeHost name, domain, Dynamic DNS, switching KVM, IDE-R or SOL off, the TLS certificate, the account the favorite signs in with, deleting an account, lowering the user consent policyAlways asks you in the MCP client. A client that cannot ask gets a refusal; make the change in the app then.
redNetwork settings, environment detection, turning AMT off on the network, the admin accountNeeds the group destructive as well, the agent must repeat the device name in confirm, and you are always asked.
  • The question shows what changes and the app’s warning. Your answer counts only for exactly these arguments and this favorite (its name, host and user). If one of them changes, the call is refused.
  • Lowering the user consent policy counts as orange because KVM, SOL, IDE-R and boot changes then run without a person at the device confirming them. If the current policy cannot be read, the change counts as lowering.
  • When the account the favorite signs in with or its certificate changes, the keychain and the favorite follow, as in the app.

Passwords of AMT accounts

Passwords of new or changed accounts are tool arguments: the agent chooses them, so they are part of your conversation with it and of the MCP client’s records. openlamt-mcp never writes them to the action log, a log line, an answer or a question.

Without TLS, the device receives the password as a digest that works like the password itself. Like the app, openlamt-mcp then always asks you before it sends one (add_user, update_user, set_admin_account), whatever require_client_confirmation says. The same holds for kvm_type_text and sol_type_text with secret on a device without TLS. A client that cannot ask gets a refusal that names the reason; use TLS, the app, or a client that can ask.

Without the app

openlamt-mcp does not need the app. On a computer without it, for example a Linux server where Claude Code runs in a terminal, the agent finds devices with scan_network and saves them with add_favorite. A Linux server usually has no system keychain: read Linux without a keychain first. Two steps stay with a person, because the agent must never see a password and must never trust a certificate on its own. The agent tells you which one to run:

openlamt-mcp password "Lab Server"
openlamt-mcp trust "Lab Server"
  • password asks for the password twice without showing it and saves it in the system keychain. If passwords.command is set, it saves nothing and tells you to store the password in your password manager.
  • trust connects to the device, shows the SHA-256 fingerprint of its certificate and trusts it after y, the same trust on first use as in the app. If another certificate is trusted already, it warns and replaces it only after y.
  • Both need a terminal: the answer cannot come from a pipe or a file. Both take --config <path> like the server.

Linux without a keychain

On Linux, the system keychain is the Secret Service, which usually runs only in a desktop session. On a server or a VM without a desktop, openlamt-mcp can read and save nothing there. Two settings in the config file replace it:

{
  "certificates": {"pin_file": true},
  "passwords": {"command": ["/usr/bin/pass", "show", "openlamt/{host}"]}
}
  • certificates.pin_file keeps the trusted certificates in openlamt-pins.json next to favorites.json instead of the keychain. openlamt-mcp trust, the question of add_favorite, set_tls_certificate and changes to favorites then read and write this file.
  • The file must be readable and writable by you only (mode 0600), or openlamt-mcp does not start. It holds no secret: a fingerprint is a hash of the public certificate. What matters is that nobody else can change it. The agent cannot write a fingerprint into it: every change follows a question you answered or a command you ran.
  • Nothing switches by itself. Without the setting, only the keychain counts. With it, only the file counts, even where a keychain works.
  • The app always uses the keychain and never reads the file. With this setting, a certificate you trusted in the app is not trusted for openlamt-mcp, and the other way round: run openlamt-mcp trust once per device, and again after you changed the host, user or certificate of a device in the app.
  • Passwords are not affected: they come from passwords.command, see Where passwords come from.
  • macOS and Windows always have a system keychain, and it protects the fingerprints better. Leave the setting off there.

Where passwords come from

For each device, openlamt-mcp takes the first password it finds:

  1. The system keychain: macOS Keychain, Windows Credential Manager, Secret Service on Linux with a desktop. The app and openlamt-mcp password save passwords there.
  2. passwords.command: a program that prints the password on standard output. For password managers such as pass, op, bw or keepassxc-cli, a file encrypted with age, or systemd-creds. No TPM is needed.
  3. Only with passwords.allow_plaintext_passwords: an environment variable or the file .env next to the config file.

The command is a list: the program, then its arguments. It runs without a shell. In each argument, {name}, {host} and {user} become the favorite’s name, host and user name. An argument must contain {host}, or the server does not start: the password is always bound to the host it goes to. {name} and {user} may be added. With pass, one entry per device:

{"passwords": {"command": ["/usr/bin/pass", "show", "openlamt/{host}"]}}

With one file per device, encrypted with age. The key file decrypts them all: keep it readable by you only.

{"passwords": {"command": ["/usr/bin/age", "--decrypt", "-i", "/home/me/.config/openlamt/key.txt",
                           "/home/me/.config/openlamt/passwords/{host}.age"]}}
  • The command gets no input and has 10 seconds. Its output, minus one line break at the end, is the password. It must print one line only: an entry of pass with more lines does not work.
  • A command that fails or prints nothing counts as no password. Its error output is never shown or logged, because it may hold secrets. Run the command yourself in a terminal to see it.
  • Why {host} is required: the agent chooses name and host of the favorites it adds. If a password were found by the name alone, a favorite with a known name and another host would receive it. A value with /, \ or .., or one that starts with -, never reaches the command.
  • Give the program with its full path: the MCP client may start openlamt-mcp with another PATH than your terminal.
Plaintext passwords are readable by every program you run.With "allow_plaintext_passwords": true, openlamt-mcp also reads the variable OPENLAMT_PASSWORD_<HOST>: the host with letters in capitals and digits as they are, every other character as _ and its hex code (. is _2E, - is _2D), such as OPENLAMT_PASSWORD_192_2E0_2E2_2E10 or OPENLAMT_PASSWORD_LAB_2EEXAMPLE_2ECOM. No two hosts share a name. list_devices shows it as password_variable, and openlamt-mcp password prints it. The same names work as KEY=value lines in .env next to the config file. The file must be readable by you only (mode 0600), or the server does not start. Every start and every answer carries a warning. Use it for a test lab, not for devices that matter.

Limit what the agent may do

Without a config file, everything is allowed.Every favorite and every action; only the orange and red settings and account changes ask. The action log is written all the same. Write a config file before you hand your devices to an agent you do not fully trust.

The config file is openlamt-mcp.json next to favorites.json in your configuration folder, or the file given with --config <path>. These are the defaults:

{
  "read_only": false,
  "allowed_devices": [],
  "tool_groups": {"read": true, "power_boot": true, "media": true, "kvm_input": true,
                  "settings": true, "users": true, "destructive": true, "favorites": true},
  "require_client_confirmation": false,
  "action_log": {"enabled": true, "path": ""},
  "kvm": {"idle_timeout_seconds": 300, "screenshot_max_width": 1280, "screenshot_max_height": 1280,
          "screenshot_format": "jpeg", "screenshot_jpeg_quality": 80},
  "sol": {"idle_timeout_seconds": 300},
  "media": {"allowed_paths": []},
  "passwords": {"command": [], "allow_plaintext_passwords": false},
  "certificates": {"pin_file": false}
}

Each key you leave out keeps its default. An unknown key stops the server, so a typo cannot leave everything open.

read_only
Leaves only the read tools: status, logs, settings and accounts, the screenshot, reading the serial console and scan_network. It never writes a setting, never turns KVM, SOL or media redirection on, and sends no input to the device. A consent request may still show a code on the device screen; that changes no setting.
allowed_devices
Favorite names the agent may use, add or rename to. Empty means all.
tool_groups
Switches the groups of the tool table on and off.
require_client_confirmation
Asks you in the MCP client before each power action, each key, mouse or typing call, each mount and media_boot_next, each settings or account change and each new favorite. Orange and red changes ask always. The question shows every key, the text to type and the full path to mount after links are resolved. Each line break (an Enter press) shows as ⏎, and invisible or direction-changing characters as their code point. If the agent marks a single line as secret, the question says that the agent chose to hide it. A client that cannot ask gets a refusal.
action_log
Writes one line per tool call to openlamt-mcp-actions.log next to the config file, or to path. It holds keys and mouse actions, mounted paths and the settings changed, but never text typed over KVM or the serial console, a consent code or a password.
kvm
The idle timeout of a KVM session (0 keeps it open until the server stops) and the default size, format (jpeg or png) and quality of screenshots. The agent may ask for another size or format per call.
sol
The idle timeout of a serial console session.
media.allowed_paths
Limits media_mount to the folders you list (absolute paths). Empty means anywhere except the protected folders.
passwords.command
The program and arguments that print a device password, see Where passwords come from. Empty means none.
passwords.allow_plaintext_passwords
Also reads passwords from environment variables and .env, with a warning at every start and in every answer.
certificates.pin_file
Keeps trusted certificates in openlamt-pins.json next to favorites.json instead of the system keychain, for Linux without one. See Linux without a keychain.

A safe start

For a helper agent that only looks:

{"read_only": true, "allowed_devices": ["Lab-Server"]}

For an agent that may act: list the devices in allowed_devices, switch off the groups you do not need (destructive, settings and users first), turn on require_client_confirmation, and set media.allowed_paths:

{
  "allowed_devices": ["Lab-Server"],
  "tool_groups": {"destructive": false, "settings": false, "users": false},
  "require_client_confirmation": true,
  "media": {"allowed_paths": ["/home/me/iso"]}
}
