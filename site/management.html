Device management

Device management shows what is in a device and what its Intel AMT is set to. Change settings, manage accounts, certificates and wake-ups, forward events or erase the drives, next to the remote screen or in a window of its own.

Sidebar and window

Click Manage in the device window. A sidebar opens next to the remote screen. The external-link symbol in its head opens the same pages in a window of their own, with a list of pages on the left.

The sidebar has a tab for each main page: Hardware, Events, Audit, Settings and Users. The last tab, More, opens a menu with further pages. A page you choose there gives the tab its name, for example Power, or Certs for Certificates. Pages marked with in the menu, such as the WSMAN Browser, need more room and open in the window.

The pages under More are Power, Wi-Fi, System Defense and Certificates. The WSMAN Browser is under Diagnostics.

Every page reads its data when you open it. The foot of a page says how old the data is, for example “Read 12 s ago”. Refresh reads again.

If the account may not read a page, the page says “This account is not allowed to read this information on the device.” Parts it may not read show “N/A”. See Limited accounts.

Hardware

The Hardware page lists system, BIOS, processors, memory, drives and the AMT version with its control mode. AMT reads these values from the device itself, so they work while the operating system is off. Sections the device does not report are left out.

Event log

The event log holds what the platform reported: BIOS progress, boot problems, sensor events and AMT messages. The device keeps it in its own memory, so it also covers times when the operating system did not run.

  • The chips All, Warning and Critical filter by severity. Filter searches the text.
  • Click an entry to see every field, including the raw data. The arrow buttons and the Up and Down keys step through the list. Copy puts the entry on the clipboard.

Event forwarding

Forwarding… in the head of the event log lists the targets to which Intel AMT sends its events as they happen, for example a SIEM collector or a monitoring server. AMT sends them as WS-Management events (WS-Eventing). OpenLAMT only sets the target on the device; it does not receive events itself and runs no listener. Syslog is not offered.

Address
The URL of the listener, starting with http:// or https://, up to 253 characters. Anything else shows “Enter an address that starts with http:// or https://.” below the field.
Delivery
Push sends each event once. With acknowledgement waits until the listener confirms each event.
Events
Which events AMT sends. The list shows the event groups the device offers, with the device’s own names. All is the default.
Sign-in at the target
None, or Digest with a user name and password for the listener. Over a connection without TLS, OpenLAMT first asks Send the key without TLS?, because the password travels unencrypted.

Adding a target asks nothing. If the device refuses it, OpenLAMT shows the reason, for example “Lab-Server refused the target: …”.

Intel AMT cannot change a target. Edit therefore opens Edit forwarding target, which only shows address, delivery and events. To change a target, click Delete Target… there (simple: “Intel AMT stops sending events to …”) and add a new one.

Audit log

The audit log records who did what on the device: sign-ins, remote sessions, power actions and changes to settings and accounts. Each entry names the Initiator (the account), the network Address it came from and the Event. Filter searches the text, and a click opens the details, as in the event log.

Which events AMT records depends on the audit policy of the device. An account needs the permission Audit log to read the log.

Audit log settings

Settings… in the head of the audit log opens the audit policy of the device. Changes are written when you click Save.

Record events
Switches the audit log on or off. Leave it on. While it is off, changes to the device leave no trace in the audit log; a few events are always recorded. Switching it off asks orange (“Changes to Lab-Server are no longer recorded.”).
When the log is full
Overwrite oldest entries keeps recording. Overwrite after a minimum age keeps entries for the Days to keep you enter (1 to 100) before it overwrites them. Stop recording keeps every entry until you clear the log; while the log is full, Intel AMT then blocks critical actions.
Space used
How many entries the log holds and how full it is.
Recorded events
Twelve groups of events in plain words, from Accounts and security to Audit log changes. A group is ticked when the device records any event of it. Ticking a group records all its events; clearing the tick stops them.
Clear the log
Clear Log… deletes every entry at once and asks red. The log then holds one new entry that says it was cleared.

An account that may read the audit log but not change its settings gets “No permission for audit settings”. Changing the settings needs an account with the Audit log permission on the device; see Accounts and realms.

OpenLAMT offers no way to pause the audit log. Intel AMT can lock the log for at most five minutes, records nothing meanwhile and refuses critical actions. OpenLAMT uses this lock only for a moment while it clears the log.

Settings

The Settings page shows and changes the Intel AMT settings of the device. AMT settings explained describes what each one does. Here is how the page works.

Switches and choices write at once. A change that can cut you off from the device asks first and names the device. Change… opens a dialog with the new value.

One Click Recovery (HTTPS boot) and Remote Platform Erase appear only where the device supports them, on newer devices (Intel AMT 16 and later). Erase drives shows “Lab-Server does not support remote erase.” and a grey button on a device without any remote erase.

Some devices do not let you change a setting remotely, for example the user consent policy in Client Control Mode. The control is then disabled, or the device answers “The device does not allow changing this setting.”

One Click Recovery and Remote Platform Erase must also be on in the BIOS of the device. If the BIOS has them off, the switch fails with “Turn it on in the BIOS first.”

The ⓘ buttons

The ⓘ next to a setting opens a short help: what it does and when you need it. Where a change carries a risk, it also says what can go wrong and how to recover. A click next to it or Esc closes it. The ⓘ buttons are on the Settings page, in the user dialog (Access and Permissions), on the Power, Wi-Fi and System Defense pages and in the audit log settings. AMT settings explained is the long form.

Erase drives

Erase… in the Danger zone has the BIOS of the device erase its drives at the next start, without anyone at the device. Use it before you pass a device on or dispose of it.

This cannot be undone.The operating system and every file on the drives are lost. Try it first on a device with a spare, blank drive.

What the dialog offers depends on the device:

  • Remote Platform Erase (newer devices): a list of what to erase. Securely erase all SSDs and Verify the erase are ticked. You can also clear the TPM, reset the BIOS settings, reload the BIOS factory configuration and unconfigure Intel AMT. Unconfiguring AMT ends remote access after the erase. What the BIOS cannot do is grey with “(not supported)”.
  • Remote Secure Erase (older devices): one choice, Securely erase the boot drive.

Drive password is only needed if the drive has a password; up to 32 printable ASCII characters. Over a connection without TLS, OpenLAMT asks Send the key without TLS? first. Erase Drives works only after you choose something and tick the checkbox with the device name. Nothing is sent before.

Then OpenLAMT asks for the user consent code if the device requires one, sets the erase and restarts the device; a device that is off is powered on. The Power menu is locked meanwhile. Open Event Log shows the progress the BIOS reports.

  • Remote Platform Erase must be on under Remote features. If it is off, Erase… shows Remote Platform Erase is off with the way to turn it on. It must also be on in the BIOS.
  • Remote Platform Erase needs a TLS connection: “Remote Platform Erase needs a TLS connection. Connect to the device with TLS and try again.”
  • A device that sleeps is refused. Wake it with Power On, wait until it runs, then try again.
  • While another power action runs, OpenLAMT asks you to wait until it ends.
  • If a step fails after the erase was set, OpenLAMT clears it again. If even that fails, it says that the next restart may still erase the drives. Do not restart the device then. Connect again and start Boot Options with Hard disk (default order): that clears the erase.

Users

The Users page lists the AMT accounts of the device. These accounts are separate from the accounts of the operating system.

Status
Enabled, Disabled or System. A disabled account cannot sign in. System accounts belong to AMT and cannot be changed.
Access
Where the account may sign in from: Network (other computers), Local (software on the device itself) or both.
Permissions
What the account may do: Power control, KVM, media, console, Hardware, Event log, Audit log, Settings. In AMT these are called realms; see Accounts and realms.

Add, edit and delete accounts

  • + Add user opens Add user: user name, password twice, Enabled, Access and Permissions.
  • A password needs 8 to 32 ASCII characters with upper and lower case, a digit and a symbol.
  • Edit opens the same fields. Leave the password empty to keep it.
  • Delete User… in the edit dialog asks orange: the user can no longer sign in, and this cannot be undone.

The admin account

The built-in admin account has every permission and cannot be deleted. Edit on it opens Change the admin account for a new name or password. This asks red: if the new password is lost, only the BIOS (MEBx) at the device can reset it. Tick Update the password in the keychain when OpenLAMT signs in with this account.

Your own account

The account OpenLAMT is signed in with carries a red *. Its Edit opens Edit your account, without Enabled and without Delete User…, because AMT does not allow either for the account of the running connection. Access cannot be Local for it, because AMT refuses that for the account of the running connection. Saving asks orange and lists the changes, because a wrong password or a removed permission can lock you out. After a password change OpenLAMT updates the keychain. If that fails, it shows the new password once so you can copy it.

Passwords without TLS

Over a connection without TLS, OpenLAMT asks Send the password without TLS? before it adds an account, changes a password or changes the admin account. AMT does not send the password in clear text, but the digest it sends works like the password. Use TLS where you can. Don’t show again hides the question; Reset Warnings brings it back.

Power

The Power page is under More. It sets when AMT stays on, and it powers the device on at set times.

Power policy

Power package
Decides when Intel AMT stays on: only while the computer runs, or also while it sleeps or is switched off. The list shows the packages the device offers, with their own names. See Power policies.
Idle timeout
Minutes after which the management engine goes to power saving (1 to 65,535). The timer starts again whenever AMT serves a request. Some power packages ignore it.
Sleep and hibernate
Read only. Shows whether the device supports these states, which explains grey entries in the Power menu.

A package that keeps remote power-on changes at once. A package that turns AMT off while the computer sleeps or is off asks orange: you then cannot power the device on remotely until someone switches it on at the device.

Wake alarms

A wake alarm powers the device on at a set time, for example for a nightly backup. The device stores at most five.

  • + Add Alarm asks for a name (up to 32 characters), date, time and Repeat: Never, Every day, Every week or Custom (every n days, hours or minutes).
  • Delete after it fires removes an alarm that does not repeat after it ran.
  • You enter times in the time zone of your computer. AMT stores them in UTC. The foot of the page names the zone.
  • AMT cannot edit an alarm. Delete it (simple) and add a new one.

Wi-Fi

The Wi-Fi page is under More. It decides when Intel AMT may use the Wi-Fi adapter of the device, and which Wi-Fi networks AMT knows. These profiles belong to AMT, not to the operating system.

Wi-Fi in Intel AMT
Off: never. While on: only while the computer runs. Always: also in sleep and while it is off but plugged in. Choose Always to reach the device without a cable while it sleeps or is off.
Sync profiles from the operating system
Intel AMT also connects to the Wi-Fi networks that Windows has saved, through the Intel drivers in Windows. These profiles do not appear in the list.
Share profiles with UEFI
Hands the AMT profiles to the UEFI firmware of the device, so One Click Recovery can boot over Wi-Fi.
Connection now
The wireless address AMT uses right now, or “Not connected”. AMT does not report the network name or the signal strength.

Profiles

  • + Add Profile asks for Profile name, Network name (SSID), priority, security and the password twice (8 to 63 characters). A lower priority number is tried first.
  • Security offers what the device supports: WPA-Personal (TKIP), WPA2-Personal (AES) or WPA3-Personal. Older AMT versions have no WPA3. Enterprise profiles (802.1X) show as “Other method”; you can delete them, not create them.
  • Edit changes a profile. AMT cannot rename one, so the name is fixed. Leave the password empty to keep it.
  • Delete Profile… in the edit dialog asks simple.
  • Over a connection without TLS, OpenLAMT first asks Send the key without TLS?, because the key travels unencrypted.
When OpenLAMT reaches the device over Wi-FiDeleting a profile or choosing Off can cut the connection you are using. OpenLAMT notices this and asks red: only a cable or the device itself brings the connection back.

System Defense

System Defense is a firewall inside Intel AMT. It filters the network traffic of the operating system, never AMT's own traffic. Use it to cut an infected computer off the network while you keep remote access through AMT. The agent watchdog on the same page reacts when software in the operating system stops working.

Intel AMT has these functions up to version 11. On newer devices the page says “Not available on this device”.

Policies and filters

  • A filter matches traffic: IPv4, IPv6 or Ethernet, inbound or outbound, a protocol (TCP, UDP, ICMP or any), ports and a remote address. Its action is Allow or Drop. It can count matches and write an event log entry on a match.
  • A policy bundles filters and decides what happens to the traffic no filter matches (Otherwise). When several policies apply, the higher Precedence wins.
  • One policy is active at a time. Activate… switches to another one, Turn Off… stops filtering. While a policy is active, the filters show how often they matched.
  • AMT cannot change a policy, filter or watchdog. Delete it (simple) and add a new one. A filter that a policy uses, or an active policy, must be freed first; the page says what to do.

Activating a policy that drops traffic asks orange: the operating system loses all network traffic the policy drops. Intel AMT stays reachable, so you can turn the policy off again on this page. A policy that drops nothing, and turning a policy off, ask nothing.

Agent watchdog

Intel AMT watches an agent in the operating system that sends heartbeats, for example a backup or anti-virus agent. OpenLAMT only sets up the watchdog; you need an agent that speaks to AMT.

  • + Add Watchdog asks for the agent name and an Agent ID. Generate creates one; the agent must use the same ID.
  • Startup timeout and Heartbeat timeout decide how long AMT waits for the first and the next heartbeat.
  • When heartbeats stop: write an event log entry and, if you like, activate a policy. When heartbeats start again: write an entry and turn the policy off again.
  • All watchdogs switch the same policy. A watchdog that would activate a dropping policy asks orange.
  • The State column shows Not started, Running, Expired, Stopped or Suspended.

Certificates

The Certificates page is under More; its tab is called Certs. It lists the certificates and key pairs stored in Intel AMT: the TLS certificate of the device, trusted roots and other certificates. Choosing which certificate AMT uses for TLS stays on the Settings page.

Type
Trusted root: a certificate authority the device trusts, for example for HTTPS boot. Certificate with key: a certificate whose private key is on the device, such as the TLS certificate. Certificate: one without a key.
Used for
TLS marks the certificate AMT presents on its TLS ports.
Key pairs
The private keys on the device and the certificate each belongs to. A key that belongs to a certificate cannot be deleted; its grey Delete… says which certificate to delete first. A key without a certificate (“none”) can be deleted, simple.

Details

A click on a row shows subject, issuer, validity, serial number, SHA-256 fingerprint, key and use. Save as File… saves the public certificate as a .pem file. The private key never leaves the device.

Import

  • Trusted root: a .pem, .cer or .crt file. Use it so the device trusts your own HTTPS server for One Click Recovery from a URL.
  • Certificate with private key: a .p12 or .pfx file and its password, for example a TLS certificate from your own certificate authority. OpenLAMT picks the certificate in the file that matches the private key. Intel AMT accepts only RSA keys. After the import, choose it as TLS certificate on the Settings page.
  • OpenLAMT reads the file while the dialog stays open, so you can pick another file or correct the password. The password is not saved, and the private key stays only in memory until it is sent.
  • Over a connection without TLS, OpenLAMT asks Send the key without TLS? before it sends a private key. A trusted root holds no secret and needs no question.
  • Importing asks nothing else. Messages you may see: “The file is not a certificate.”, “Wrong password for the .p12 file.”, “No certificate in the file matches its private key.”, “The key in the file is not an RSA key.”, “The device already has this certificate or key.” and “Lab-Server has no space for more certificates.”

Delete

  • Delete Certificate… in the details removes a certificate. For a certificate or key nothing uses, it asks simple.
  • Deleting a trusted root asks orange: the device no longer trusts servers signed by this root, and HTTPS boot from such servers stops working.
  • The device refuses to delete the certificate it uses for TLS. OpenLAMT then shows Certificate in use with Open Settings: choose another TLS certificate there first.

WSMAN Browser

The WSMAN Browser shows the raw data of Intel AMT: the classes of the WS-Management interface and their values. Use it to look up a setting OpenLAMT does not show, or to compare devices. It only reads.

Open it from More > WSMAN Browser. It opens in the management window, under Diagnostics.

  • The class list groups the classes by AMT, CIM and IPS. Find class filters it.
  • A click reads every instance of the class. Several instances get chips “Instance 1”, “Instance 2” and so on.
  • Known numeric values show their meaning, for example 1 (Enabled).
  • Copy as XML copies the instances to the clipboard, with values in full length.
  • A class the device does not have, or the account may not read, shows a short reason instead.
  • A read stops at 200 instances or 1 MiB of data and then says “Truncated”.
