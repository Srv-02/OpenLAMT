This computer

OpenLAMT can read Intel AMT on the computer it runs on. If AMT is off or not activated yet, it can turn it on and activate it, so that you can reach this computer from another one.

When it appears

The section This computer sits in the sidebar above Favorites. It appears only when this computer has an Intel ME device (the Intel management engine that runs AMT):

  • Linux: the Intel ME driver provides /dev/mei0.
  • Windows: the Intel MEI driver is installed and its device is present.
  • macOS: never. Intel Macs have an Intel ME, but macOS has no driver for it.

OpenLAMT looks for the device once at start, without administrator rights. It only checks that the device exists. It does not open it and sends nothing to it. If you install the driver later, start OpenLAMT again.

An Intel ME alone does not mean that the computer has Intel AMT. Many computers have an Intel ME without AMT. Only Check tells you.

Check

Select This computer in the sidebar and click Check. Until the first check, the card says Not checked yet: “Check reads Intel AMT through the Intel ME driver of this computer. Nothing is changed.”

The Intel ME driver only answers programs with administrator rights. OpenLAMT itself never runs with them. Check therefore starts a short helper (the OpenLAMT program with --local-check), and your system asks for the rights first:

  • Linux: pkexec (polkit) asks for the password of an administrator.
  • Windows: the User Account Control (UAC) prompt appears.

No dialog of OpenLAMT comes before the prompt. If you cancel it, nothing is read and nothing changes.

The helper only reads: the AMT version, whether AMT is on, the activation, the network interfaces of AMT, its UUID and DNS suffix. It reads no password and no AMT account. It does not start LMS or any network service. It prints its answer and exits.

OpenLAMT keeps the last result, also across restarts. The sidebar row shows it as its second line:

Version
The full AMT version, for example 16.1.25.
Activation

No Intel AMT found

The card No Intel AMT found says: “The Intel ME did not report Intel AMT. Possible reasons:”

  • Intel AMT is turned off in the BIOS.
  • The Intel ME driver is missing or outdated.
  • This computer is not a vPro platform.

Check the BIOS settings first: AMT must be enabled there. Then install the current Intel ME driver of the computer maker and click Check again. Without a vPro processor and chipset, the computer has no Intel AMT.

Set up Intel AMT

Below the result, the Setup card offers exactly one next step, depending on the last check. Each step asks for administrator rights like Check, makes the change and reads AMT again. The card then shows the new state.

The checkbox of each confirmation names this computer: I understand the risk for this computer (desk-01). With no result, no Intel AMT or an unknown activation, the Setup card is missing.

Turn on

“Intel AMT then answers on the network. Turning it on from here needs AMT 16.1 or newer.” Turn On… opens Turn on Intel AMT on this computer? with the warning: “Intel AMT starts answering on the network (ports 16992 and 16993). Anyone with an AMT password can then control this computer, also while it is switched off.” Turn On AMT switches it on.

If the firmware does not allow the change from the operating system, there is no button. Turn AMT on in the BIOS extension (MEBx) instead and check again.

Activate in Client Control Mode

Activate… opens Activate Intel AMT in Client Control Mode?. Enter the new Admin password twice. The user name is admin. The password must have:

  • 8 to 32 ASCII characters,
  • an upper case letter, a lower case letter, a digit and a symbol,
  • none of the characters " , :.

Activate works only when the password meets these rules, both fields match and the checkbox is ticked. OpenLAMT does not store the password, not even in the keychain. Note it, you need it to connect.

Client Control Mode asks for a code at the screen.Every KVM session and every remote boot asks for a 6-digit code shown on this computer’s screen. Without someone at the screen, KVM does not work. For a computer without a person in front, set up Admin Control Mode (ACM) in the BIOS (MEBx) instead.

After the activation, add this computer as a favorite on another computer, with the user admin and the new password. A network scan from there helps you find it. See User consent code for the code dialog.

Before it sends the password, OpenLAMT checks the AMT ports 16992 and 16993 on this computer. Only Intel’s LMS service may listen there, or nothing. If another program listens, the activation stops: “Another program uses the Intel AMT port 16992 on this computer. Nothing was changed.”

Deactivate

In Client Control Mode the card shows Deactivate Intel AMT: “Deletes all AMT settings and accounts on this computer.” The red Deactivate… opens Deactivate Intel AMT on this computer?. Deactivate removes the activation with all accounts, certificates, Wi-Fi profiles and network settings in AMT. Remote access stops until you activate AMT again. Favorites of this computer on other computers stop working.

Admin Control Mode

In Admin Control Mode there is no button: “Deactivate Intel AMT in the BIOS (MEBx). Admin Control Mode cannot be deactivated from the app.” OpenLAMT does not set up Admin Control Mode either. Use MEBx for that.

Beta

Check, the setup buttons and their dialogs carry a grey Beta pill with the note “Uses a preview of Intel’s rpc-go library.” OpenLAMT reads and changes AMT on this computer through that library, and the version it uses is a preview release. Everything else in OpenLAMT does not depend on it.

If a result looks wrong or a step fails, please report it with your system, the AMT version and the exact message.

Messages

“Administrator rights were not granted. Nothing was changed.”
You cancelled the prompt, or the password in it was wrong. Click the button again and confirm the prompt.
“OpenLAMT needs pkexec to ask for administrator rights. Install polkit and try again.”
Linux only. pkexec asks for the administrator rights. Install it from the packages of your distribution: it is part of polkit, on Debian and Ubuntu in its own package pkexec.
“Intel AMT refused the change: …”
The firmware did not carry out the step. The reason follows the colon. The card shows the state read afterwards.
“Intel AMT refused the change: Intel AMT may be turned off in the BIOS (MEBx).”
The activation failed on AMT before 16.1. These versions do not report whether AMT is off. Turn AMT on in MEBx and try again.
“Another program uses the Intel AMT port 16992 on this computer. Nothing was changed.”
A program other than Intel’s LMS listens on the AMT port, so OpenLAMT did not send the password. Stop that program and activate again.
The card shows “No Intel AMT found” after a step
The Intel ME no longer reports Intel AMT. See No Intel AMT found.
